## 各类数量独立核算

- `ProductionAllocation`：精确订单明细的**生产计划份额**。手工匹配产出行，电镀匹配 `receive_part_id or part_id`，不按原色投入匹配。
- `OrderMaterialDemand`／`MaterialProductionAllocation`：精确商品订单行的一级 BOM **配件理论需求快照／备料生产计划份额**。与直接商品份额共用同一物理产出的计划容量，但不计入最终商品的生产安排或出货数量。
- `StockReservation`：一条订单明细在公共现货上的**待发预留**。取消预留仅释放可用量，不是退货或回库。
- 加工发料／回收／损耗：仍使用原实际单据；回收进入公共库存。生产关联不是实物所有权。
- `CustomerShipment`／`CustomerShipmentItem`：独立的实际客户出货凭据，精确引用订单行，并保存对应库存流水 ID。
- 订购量、生产计划、回收量、预留量、实发量不能互相相加冒充交付。部分发货的行不计入「已全部发货 X / Y 项」。

公共现货可直接发给客户，不强制关联生产、不强制有 BOM，也不强制先预留。整批生产实收或金额不会复制给每个客户。

## 生产分配与新建／追加

生产计划可跨订单共享，保持同款重复订单行的身份。单行所有来源之和不超订购量，跨订单所有份额之和不超同一产出计划量。修改已有份额携带来源 `revision`；过期保存拒绝，不覆盖其他客户。

确认正数手工／电镀份额时，在同一事务将客户订单从「待生产」改为「生产中」，不必等待加工单实际发出；按明细新建／追加制作及兼容旧关联／批次关联商家也遵循此规则。仅查看候选、零数量或失败请求不启动，采购关联不视为手工／电镀生产。解除关联不自动倒退状态，已完成／已取消历史记录不重新打开。未对既有历史状态批量回填，也不在 GET 查询时写状态。

「订单关联」直接列出匹配本单商品的已有活跃手工单，按单号自然倒序分组、逐产出展示商家、阶段、计划量、未分配计划和本单已有份额，支持独立的手工商家筛选及单号／商家／商品关键词组合搜索。分组前按商品类型与编号匹配当前订单，仅展示相关产出；整单无相关产出时不展示该手工单，也不将其商家加入筛选选项。右侧「分配给本单」进入精确订单行数量编辑，已有份额显示「调整本单分配」；不再通过两个下拉框选择手工单／产出。同一手工单多条产出不合并。点击选择不会写入，仍须确认正数份额后保存；旧归属冲突、单位不一致和无可用订单明细的产出禁用并说明原因，已结清／归档手工单不进入候选。

从订单明细「安排制作」时：

1. 固定当前订单、具体行及目标商品／单位，只创建一条新产出。
2. 分别填写整条产出计划和本行份额；差额是公共**未安排计划**，不是现货。
3. 默认新建独立手工单；仅明确选择同商家、未归档、`pending` 的具体单号才追加。
4. 追加保留原日期、收货码和已有材料／产出行身份；新输入与新产出始终新增行，不合并旧行数量。
5. 服务端锁定并重新检查目标状态；手工发出也锁同一父单，避免追加与发出并发漏发材料。
6. 新产出和本行分配在同一事务保存；失败不残留半张制作单。`ProductionCreation` 保存请求指纹与结果，同一请求准确重试不会重复建单／追加，改变内容则拒绝。
7. 页面可读取当前 BOM 辅助填写材料，也可手动输入；这些仍是制作单的计划投入，不自动确认上游物料份额。独立配件需求与产出关联见下节；保存制作单不会扣料、预留、回收或发货。
8. 输入新手工商家名称时，同事务补入商家名录；失败连同商家一并回滚。同名同类型商家并发创建使用唯一约束冲突忽略，保留已有 ID 和日期，不改其他类型商家。

保存中／网络结果未确认时，冻结此次请求内容与请求键；禁止 Escape、关闭弹窗、页面离开和同路由切换订单，刷新时触发浏览器离开提示。准确重试查询原结果。**这不是跨刷新恢复机制**：用户强制刷新／关闭、登录跳转等情况下尚未持久化待核对请求，应先核对原制作结果，不能把新请求当作安全重试。

独立手工创建和旧订单批次关联商家入口也已去除「同商家同日自动合单」，共同使用 `append_to_order_id` 显式选择目标。单独建公共库存生产单仍可用，不需要客户订单。

## BOM 配件备料关联（本轮修复）

- 根因有两层：手工产出区的旧「批量关联订单」提交了 `HandcraftPartItem` 领料行，且旧服务要求先生成 `OrderTodoItem`。订单工作台已不再生成旧清单，而原新数量分配又只匹配直接购买商品，导致「订单商品 → BOM 配件 A → 手工产出 A」无法关联。
- 手工详情改用 `ProductionOrderLinkDialog.vue`，按**真实产出**匹配所选订单的商品制作／配件备料需求，展示具体订单明细、客户货号、理论需求、已安排与可分配计划。多条同款产出的建议共用临时需求账本，不会每条都重复建议整份缺口；选择、预览、取消不写入。
- 不恢复「生成配件清单」作为前置条件，也不伪造直接购买的订单配件行。`GET /production` 动态返回当前一级 BOM 理论需求；只有明确确认正数配件份额才建立／更新独立需求快照。
- 需求身份为具体 `order_item_id + material_part_id`，同款重复商品行互不合并。手工份额为整数；电镀配件份额最多四位小数，仍按收回目标匹配，不按电镀投入匹配，不自动换算单位。
- 商品制作与配件备料共用产出容量及来源 `revision`；同一配件需求的所有手工／电镀来源合计不超过该行理论需求。批量提交在同一事务预先锁定全部来源并校验旧版本，整体替换本单提交的份额，支持来源间转移；任一失败整批回滚，其他客户份额不变。
- 配件确认另携带 `demand_revision`；BOM、订购量或配件单位改变后，旧预览被拒绝。GET 不重写快照，也不改已有份额；订单生产页明确展示原需求与变更提示。重新确认时核对当前理论总需求，填 0／移除本单份额可释放旧安排，即使 BOM 行已删除或单位已变化。订单减量／删除与产出减量／更换目标／删除也受份额保护。
- 订单页新增「配件备料需求」并将配件产出纳入既有手工候选与电镀来源；手工主列表仍只展示已确认关联。产出用途区区分「商品制作／配件备料」，反向追溯同一订单与明细。客户分拣投影两类份额，锁定已分数量、保留未分余量，不推算各客户实收。
- 确认正数配件份额也自动将客户订单从「待生产」改为「生产中」，取消份额不倒退；不修改实收、库存、预留、领料、客户出货或最终商品完成量。物料现货分配、公共生产份额独立需求和递归排产不在本轮范围。
- 旧清单／关联／批次继续保留；遇到未量化旧归属时阻止冲突新份额，不猜历史数量，不自动迁移。新增两张表使用现有启动建表机制，不进行历史回填；发布前仍需按既有备份与迁移流程审查。

## 新单履约、历史核对、库存保护与实际出货

- 新建订单在创建事务内建立 `OrderFulfillment`，直接使用统一流程，不再手动启用。读取、启动及更新不自动激活任何历史订单。
- 仅历史待生产／生产中订单显示就地核对；明确核实没有历史实际客户发货后才从 0 开始记录。已有实发或无法确认时不得启用；历史已完成／已取消订单保持只读。
- 逐笔履约整单保留记录，不提供硬删除；可以在满足保护条件时取消。历史整单删除兼容测试使用显式历史夹具，不把新单当成旧单。
- 预留写入锁客户订单与商品库存，并核对当前预留版本、行剩余待发和公共可用量。
- 所有库存增加／扣减经过共同库存服务。事务级 PostgreSQL advisory lock 使用 `allen-stock:{kind}:{product_id}`；即使旧库存 ID 无商品目录行也受保护。
- 原有领料、其他出库和旧流程扣库不能占用其他订单／明细的预留。
- 出货草稿不占库、不扣库。确认时重验全部行、订单状态、剩余待发与库存；同商品的公共消耗先汇总，全部通过后才变更。
- 只释放选中行本次实际消耗的自身预留，再通过共同库存服务扣减。未选中兄弟行的预留不被挪用。
- 出货创建请求键跨订单串行校验；同内容重试返回原单，换内容拒绝。重复确认不重复扣库，订单完成后准确重试仍有效。
- 所有行足额实发才完成订单；不调用旧 `update_order_status()` 完成扣库，防止重复出库。新完成路径允许缺失 BOM 的成本快照，但明确标记成本不完整；旧成本快照调用仍严格校验。
- 已实际出货不支持直接作废或重开；退货／冲销需另行设计，不能通过改状态伪造回库。

实际入库目前使用现有库存页的新标签入口；返回出货核对页保留选择，须刷新库存并重新核对。**尚未实现 Demo 的页内入库后返回弹窗**，也不会自动按缺口补库。

## 兼容与数据边界

新增表为加法变更，正常启动可通过现有 `Base.metadata.create_all()` 建表。未对业务库执行迁移、回填或任何数据操作；正式迁移方案仍须审查和备份。

旧 `OrderItemLink`、批次引用、手填客户归属保留。缺少精确行／份额时不猜测回填，视为未量化的独占待核对归属。新数量计划与旧整行写入保守互斥，避免重复安排。

生产写锁顺序为客户订单 →（涉及配件确认时）按商品编号排序的 BOM advisory locks → 排序后的生产父单／产出行；BOM 修改使用同一 advisory lock。库存／出货为客户订单 → 出货单 → 排序后的商品 advisory locks。来源计划与客户需求的容量均在锁内核对。

## 接口概要

- `GET/PUT /api/orders/{id}/production`：本单需求、精确候选来源、替换本单在一条产出上的份额。
- `POST /api/orders/{id}/production/batch`：原子替换多条产出的本单份额；手工批量关联使用，需要 `orders` 和 `handcraft` 权限。配件条目在原 `order_item_id/quantity` 外增加 `material_part_id/demand_revision`，直接商品条目原契约不变。
- `POST /api/orders/{id}/production/handcraft`：按具体行原子新建／显式追加手工产出及计划分配，需要 `orders` 和 `handcraft` 两种权限。
- `GET /api/{handcraft|plating}/{id}/production-uses`：产出各客户份额及公共未安排计划。
- `/api/fulfillment/orders`、`/orders/{id}`、`/orders/{id}/activate`、`/orders/{id}/reservations/{line_id}`：履约摘要、激活、行级预留。
- `/api/fulfillment/shipments`、`/shipments/{id}`、`/shipments/{id}/confirm`、`/shipments/{id}/void`：真实出货账本。

履约接口沿用 `orders` 权限；真实入库沿用 `inventory` 权限。其他生产接口沿用原模块权限。没有新增匿名接口。
