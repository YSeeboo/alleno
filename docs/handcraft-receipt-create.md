# 新建手工回收单

## 本轮范围（2026-11-24）

- 正式入口：`/handcraft-receipts/create`，沿用现有路由、权限及创建接口。
- 采用已认可 Demo 的信息结构与交互，但不导入 Demo 文件，也不复制其侧栏、插画或视觉皮肤；使用现有 Naive UI 卡片、表单、弹窗及绿色主题。
- 桌面为左侧录入、右侧实时核对；窄屏改为单列，手机另有固定底部核对栏。桌面核对栏在短屏可独立滚动，手机核对及退料弹窗的内容可滚动、底部操作可见。
- 只修改前端页面、退料组件、工具、测试及本文档；不修改后端、数据库、业务规则、依赖或线上配置。用户已授权合并提交、推送并部署正式服；实际发布结果以服务器发布记录为准。

## 来源与录入

1. 选择商家，或输入五位回执编码后按回车／点击“定位”；回执定位后锁定商家，仅展示该回执的来源。
2. 使用 `include_settled: true` 获取该商家／回执的完整来源列表。名称、编号、手工单、单据日期和进度均在前端筛选，每页 20 条；筛选、翻页不会丢失已选行或输入。
3. 产出以来源明细独立选择，同款不同来源不合并。来源键为 `output_ID`／`material_ID`，产出与材料数据库 ID 相同也不冲突。
4. 选中后展开实际回收数量、手工单价和本行金额；重量默认折叠，桌面和手机均可录入 g／kg，重量不参与手工费计算。取消勾选再选回保留当前来源的输入。
5. 数量默认取来源结清余额；已结清或超结清来源默认留空，必须主动填写实际数量。产出要求正整数，允许超出未收数量，并在明细、核对区域及确认预览中提示。
6. 配件退料独立编辑和展示，不计手工费。可仅退料而不选产出，数量最多四位小数，允许实际超收。退料弹窗使用独立草稿；取消或关闭不修改主单，筛选不清空已选退料，已选但数量空白的行仍保持勾选并阻止确认。

### 数据口径

- 来源 `received_qty` 是包含实收与已确认损耗的**结清计数**，不是累计实收；未收数不再次扣除损耗，未收差额也不会自动记为损耗。
- 来源 `created_at` 展示、筛选为**单据日期**，不标为准确发出时间，也不改用浏览器时区转换后的日期。
- 数量按各自单位分别汇总，不跨单位相加；刷新后单位与最新来源保持一致，数量、价格、重量不被默认值覆盖。
- 空单价表示待定价，零单价是明确零价。金额复用电镀回收工具的七位小数算法：先舍入单价，再逐行舍入金额，最后汇总；实际存储金额仍以服务端为准。
- `is_output: true` 的产出配件仍使用 `handcraft_jewelry_item_id`；只有材料退料使用 `handcraft_part_item_id`，不附带价格与重量。

## 草稿及创建保护

- 切换商家、定位不同回执或清除定位，有已选明细时必须确认。确认后只清空来源相关选择、数量、价格、重量及退料，保留日期、备注和付款状态。
- 来源请求和编码定位都有序号／上下文保护，旧响应和卸载后的响应不能覆盖当前来源。
- 刷新失败保留草稿，提供重试并阻止提交；刷新后消失的来源显式标为不可用，不静默删除、不悄悄漏交，必须移除或恢复来源。
- “核对回收单”先验证并展示确认预览，再调用既有创建 API；空数量、非法精度、商家不符或失效来源不能提交。
- 创建中锁定录入、重复提交与路由离开；失败保留完整草稿及预览，可重试。成功后记录已创建 ID 并持续锁定本次创建，不依赖跳转是否成功。
- 配件不足仍按服务端结果提示；成本变动独立确认，不能用遮罩／Esc／关闭按钮跳过。成本失败只重试成本更新，也可主动跳过，不重新创建回收单。
- 成功详情链接及返回入口继续保留汇总／产出总览上下文。当前保护是页面级防重复，不新增服务端幂等协议。
