# 新建电镀回收单

## 本轮范围

- 参考「新建电镀单」统一面包屑、标题、录入状态、基本信息、分区标题及底部汇总操作区。
- 待回收配件选择与本次回收录入分区：来源单据、发出 / 已回收数量、剩余数量在选择区显示；已选明细录入数量、实际重量及单价，并预览小计。
- 基于页面实际内容宽度切换桌面表格式布局与手机双列卡片；手机不依赖横向滚动录入。
- 保留既有创建 API、回收入库、来源关联、付款及配件成本差异确认流程。没有修改后端、正式配置、生产数据或迁移脚本。

## 数据与交互边界

- 按商家读取完整待回收列表，在本地按发出 / 回收配件编号、名称及来源发出日期筛选；多个搜索词均需匹配，大小写不敏感。
- 已选集合独立于筛选列表，以来源电镀明细 ID 区分，同款配件的不同来源不合并。提交所有已选行，不静默忽略被筛选隐藏的行。
- 切换商家、清空全部明细需明确确认；单行移除后重新勾选仍保留本页已填数值。明确清空或切换商家时才清除这些输入。
- 数量默认使用来源剩余数量；单位继承来源（包括历史单位），重量单位继承来源，缺省为 g。不同计量单位的回收数量分别汇总，不换算单位。
- 单价空值为待定价，0 为免费。预览与后端相同：先将单价 ROUND_HALF_UP 到七位，再按数量计算各行七位小计，最后合计；最终存储金额仍由服务端决定。
- 刷新来源不会重写用户已填数值。来源消失、超出最新剩余数量或商家不符时阻止提交；列表读取失败保留已填明细，提供重试，不当成空列表。
- 创建请求期间锁定表单、切换商家、重复提交与路由离开。成功后锁定本次创建，成本确认弹窗不能通过遮罩、Esc 或关闭按钮意外退出；同步成本失败只重试成本写入，不重建回收单。
- 成本同步仍需用户主动确认；跳过不修改配件成本。创建成功使用 replace 进入详情，避免浏览器返回到刚提交的创建表单。
