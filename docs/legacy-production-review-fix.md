# 旧参考批次误锁生产安排修复

## 规则与数据边界

- 旧商品批次只有在批次绑定加工单、或商品记录绑定产出行时才阻止新增生产份额。任一引用存在即保守保护，包括已完成、归档及来源失效的历史；不自动清理引用。
- 两个引用都为空的旧批次仅作参考，不视为已生产／已安排量，不阻止新建、明确追加或分配其他合格产出。
- 旧材料清单的手工投入和采购关联不是生产产出归属，不阻止商品配件／BOM 备料分配；电镀产出、手工产出及原直接商品产出关联继续保护。
- 不按客户同名、旧批次数量、整批实收量推算订单份额；同款重复明细仍按精确订单行独立分配。
- 不删除、转换、回填旧关联，不改库存、实收、损耗、回收和出货数据；本补丁没有数据库结构变更。
- 生产容量判断与删除保护分开：未绑定产出的参考批次，以及投入／采购关联，仍保护对应商品明细不被删除。

## 页面

- 「旧记录核对」区增加「查看旧记录」只读弹窗，区分参考批次与有来源绑定的批次，列出旧数量、当前订购量及差异。
- 可以从弹窗展开并滚动到完整批次／材料关联记录；有加工单编号时保留原加工单链接。
- 新安排制作时提示先核对历史加工与库存：新份额为 0 不代表从未生产，填写的应为实际仍需制作数量。

- 后端回归仅使用临时创建、名称以 `_test` 结尾的独立 PostgreSQL 数据库，结束后精确删除测试库，不使用业务库。

- 前端测试覆盖真实弹窗模板、旧数量差异、来源链接、转义、历史展开／滚动／聚焦及切单清理上下文。
