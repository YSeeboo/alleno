# 订单页面整合 Demo

本文件记录独立交互原型及其评审边界。**原型自身不调用业务接口、不修改账户或数据库**；用户批准后的真实两页签整合另见 `docs/order-production-implementation.md`，不能将原型能力等同于真实功能完成情况。

- 地址：<http://localhost:5173/demos/order-integration/index.html>（Vite 开发服需保留 `index.html`）
- 文件：`frontend/public/demos/order-integration/`
- 风格：接近本地应用的 240px 深色侧栏、AL／ALLENOP 标识、无整站顶栏、浅灰底、绿色强调、原有标题／卡片／表格尺度。
- 隔离：仅使用虚构内存数据，刷新重置，不读取登录态、不持久化，CSP 禁止网络连接与表单外部提交。复用的 `order-fulfillment/domain.js` 也仅是原有虚构 Demo 引擎。

## 评审重点

只保留「订单详情／生产安排」两个订单页签，不再设「订单资料与旧流程」模块。

### 订单详情

基本信息与资料编辑、可展开的条码／唛头／备注／参考图、统一商品明细（商品、客户货号、数量、单价、金额、生产安排、预留、已出货）、本单出货记录、费用与成本、操作记录。

支持编辑资料／要求／明细、添加同款独立行、删除无业务记录的明细、修改包装费、预留／取消预留、从具体行安排制作、选择实际出货行与数量、保存草稿、核对库存、确认出货、作废草稿，以及真实入库演示后返回核对。

### 生产安排

本单制作需求、已关联任务（本单／其他客户／公共计划份额分开）、从已有任务分配、默认新建制作与明确追加、加工单用途追溯、按任务查看 BOM 备料与整单理论 BOM 汇总、调整现货／上游电镀备料来源。

缺少明确数量的原有关联只在对应订单的生产安排下折叠提示，不计入已安排数量，不另设一套操作流程。

### 存量异常就地提示

订单选择框提供正常订单、历史实发待核对订单和历史已完成订单。只有待核对示例显示历史核对提示；正常订单无启用步骤。必须明确确认无历史实发才可从 0 开始记录；无法确认或已有实发时取消，不提供无凭据补记。历史完成订单只读，数量展示为未核实，不补出货、不动库存。

### 跨订单入口

侧栏「库存备货／出货管理」与订单内操作共用同一组演示数据，可反向进入订单，不重复录入。

## 原型边界

- 原型用于确认信息布局和交互，不代表真实系统已经完成整合。
- 不模拟完整加工执行、附件上传、异常单据补录、完整成本结算或完整审计；加工单详情明确说明执行操作仍属于原加工模块。
- 费用区明确区分订单费用、理论用量和待核算实际成本，不用 BOM 理论值冒充已结算成本。
- 已有制作、预留、关联和出货记录会限制商品替换、减量或删除，避免修改破坏原明细身份。

## 验证

`frontend/tests/orderIntegrationDemo.test.mjs` 执行真实原型渲染和虚构领域逻辑，覆盖两页签结构、资料整合、数据隔离、明细身份保护、共享计划、预留、出货幂等及存量核对。

2026-11-19 本轮验证：新增 18 项原型测试通过，前端全量 193 项测试通过，生产构建与 `git diff --check` 通过（构建仍有原有 auth 静态／动态导入提示）。浏览器检查了桌面和 375px 手机布局、资料／货号编辑、共享任务调整、明确追加独立产出、部分出货，以及库存不足时登记真实入库后返回核对。手机端宽表内部滚动，整页宽度保持 375px。所有交互均发生在虚构内存数据中，无业务 API 请求。
