# 饰品结构与搭配 · 交互 Demo

入口：同目录下的 `jewelry-structure-demo.html`。可直接用浏览器打开，也可由静态 HTTP 服务预览；无构建、外部依赖或业务接口请求。

## 建议体验顺序

1. 使用“耳钉链条吊坠款”，在批量表切换默认“小珠版 / 大珠版”，观察珠子配件、数量与链长一起变化。月亮款单独指定方案，不跟随本批默认切换。
2. 每行选择不同吊坠；打开“调整 / 用料”更改链长、删除珠子或增加开口圈。只修改这一件，不增加模板或影响其他行。
3. 预览最终 BOM 并确认生成。每行产生一件独立饰品，不做珠子与吊坠的笛卡尔积，不自动归为同款。
4. 返回工作台修改耳钉默认用量或保存搭配方案，再看“已生成饰品”：原有 BOM 不变。
5. 删除结构中的珠子位置：引用珠子的方案会显示不兼容并阻止生成，可显式移除失效引用，不会把珠子加回结构。
6. 切换“耳钉尾链吊坠款”，体验另一种结构。也可自由增删、命名组成位置，另存新结构，或把单件调整另存为常用结构。

## 演示边界

- 所有数据和用量都是虚构示例，单位按生产 **1 对**饰品填写。
- 数据仅存于页面内存。刷新或重置会恢复初始示例。切换结构会重置未保存草稿和本批行。
- 模板草稿实时参与本批预览；保存模板才可复用。方案编辑需要保存才影响待生成饰品。
- 单件调整优先于方案并保留，直到手动清除。模板或方案保存均不更新已经生成的饰品。
- 吊坠是示例中的逐件选配位置；其他位置也可在单件用料窗口替换、增删。
- 链条与尾链使用虚构的 `cm` 库存单位；不做长度与重量换算，也不从珠子尺寸猜用量。
- 同配件在多个位置出现时，生成的实际 BOM 合并其用量。
- 不涉及实际价格、库存、订单、款式分组、数据库模型或 API 改造。
- 已投产批次的用料锁定属于未来正式设计，本演示仅展示生成饰品的独立 BOM，不声称已实现生产版本保护。

## 验证

使用浏览器验证了方案联动、默认与单独指定、单件配件增删与用量覆盖、最终预览、批量生成、已有 BOM 独立性、方案兼容性及修复、结构和方案另存、重置；检查桌面与移动端布局。批量表在窄屏可横向滚动。
