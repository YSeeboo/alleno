- 日期：2026-11-10

- 实施计划：`docs/superpowers/plans/2026-11-10-jewelry-structure-schemes.md`

## 1. 解决的问题

一批饰品可能共用耳钉、链条和珠子，但吊坠不同。珠子尺寸变化时，珠子配件、珠子数量和链条用量也需要一起调整。

现有模板保存的是一份确定的配件清单，导致每种搭配都要复制整份模板。目标不是强行减少所有模板，而是让不同结构有各自模板，同一结构内的联动差异可以复用，偶发差异不必生成新模板。

不以“款式 / SKU 重构”代替这个需求。制作结构复用与商业款式分组是两件独立的事。

## 2. 确认的三层关系

```text
结构模板：需要哪些组成位置、默认配件和用量
    ├─ 联动搭配方案：需要一起变化的配件与用量
    └─ 批量创建：共用默认 + 每行方案 + 逐位置选配 + 单件调整
                ↓
        具体饰品 + 确定且独立的实际 BOM
```

### 2.1 结构模板

- 组成位置可自由添加、删除、命名和排序，不硬编码为耳钉、链条、珠子、吊坠。
- 例如“耳钉＋链条＋珠子＋吊坠”和“耳钉＋吊坠＋开口圈＋尾链”都可以保存。
- 每个位置有稳定标识、显示名称、默认配件（可暂缺）、默认单件用量。
- 位置名称不充当关联键；重命名不应使方案失效，删除后新增同名位置也不应自动继承旧方案。
- 正式版允许把任意位置设为逐件选配，不只限于吊坠。Demo 中的吊坠是最常见示例。
- 模板用量的基准为 **1 个销售单位**，可以是一对、一件或一套。正式版不得沿用 Demo 硬编码的“1 对”。
- 结构保存为独立可复用记录；另存结构不复制一堆已不适用的方案。

### 2.2 联动搭配方案

- 方案属于某个结构，按位置保存需联动的配件、用量设置，其余位置沿用结构默认。
- “小珠版 / 大珠版”是人工配置的联动设置，不从直径推算用量。
- 不把可独立选择的吊坠编进每个珠子方案，不自动生成所有搭配组合。
- 删除结构位置后，引用该位置的方案标记为不兼容，不得在解析时加回已删除配件。
- 用户可显式清理失效引用、调整方案或选择其他方案，不能无提示地修复或忽略。
- 同样要验证新增必需位置、配件停用或删除、用量与单位等问题。结构能解析不代表最终 BOM 已完整。
- 保存方案只影响随后解析的待创建配置，不反向更新已经生成的饰品。

### 2.3 具体饰品及 BOM

- 每个批量表格行生成一条独立饰品记录，有现有规则下的编号、类目、单位、价格等信息。
- 创建前必须解析出真实配件和确定用量；生产、成本和库存继续读取现有实际 BOM，不在生产时临时解析模板。
- 同配件出现在不同位置时，最终 BOM 按配件标识合计用量，保留位置来源供预览核对。
- 结构 / 方案的来源信息用于解释与追溯，不是动态用料继承关系。
- 不自动创建款式组，也不合并不同饰品的库存。

## 3. 批量创建流程

1. 选择已保存结构，或编辑结构草稿。
2. 设置本批默认搭配、饰品类目和销售单位等共用信息。
3. 添加待创建行，每行填写名称，并选择沿用默认或单独指定方案。
4. 逐行选择吊坠等选配位置；必要时在单件窗口替换配件、修改数量、增删位置。
5. 预览每行的最终 BOM、库存计量单位及不完整项。
6. 确认后原子性创建本批饰品及其独立 BOM。

交互规则：

- 切换本批默认时，只影响沿用默认的行，单独指定方案的行不变。
- 单件调整优先于方案；切换方案不静默清掉单件调整。显示调整标识，并提供显式清除操作。
- 单件调整可以只用于该饰品；反复使用时才另存为常用结构或方案。
- 任意行缺名称、缺必需配件、用量非法或方案不兼容，整批不能确认。
- 结构和方案的未保存草稿要有明确标识，不把创建饰品当成隐式发布模板。
- 正式版切换结构、离开页面或关闭编辑窗口时，应对未保存内容提供确认；Demo 的重置提示不是正式版的防丢失机制。
- 预览后若模板、方案或待创建行变化，应使预览失效并重新确认，不能提交与所见不同的 BOM。

## 4. 接入现有系统的建议

### 4.1 替换旧模板模块，保留实际业务数据

替换前代码（以下旧模板文件已移除，作为设计背景保留）：

- `models/jewelry_template.py`：旧模板与确定配件行。
- `services/jewelry_template.py`：模板导入对目标 BOM 做 upsert。
- `services/jewelry.py`：现有饰品编号及独立记录创建。
- `models/bom.py`、`services/bom.py`：实际配件用量。
- `frontend/src/views/jewelries/JewelryList.vue`：新增、复制、同款与从模板创建。

按用户补充要求，直接用结构 / 方案工作台替换旧模板模块，不并行维护新旧两套模板，不开发旧模板兼容层或转换入口。

- 旧 `jewelry_template_item` 配件行和 `jewelry_template` 模板记录均可全部删除，不转为新结构或方案。
- 旧模板模型、服务、API、前端请求、管理页面及相关入口随新功能统一替换或移除，不保持旧接口语义。
- 原“从模板创建”入口改接新工作台；饰品详情中的旧模板导入入口移除，不保留一个依赖旧数据的失效按钮。
- 现有饰品、实际 BOM、编号、`style_group`、库存和历史单据保留，不删除、不重算。旧模板的删除不会删除其曾经生成的饰品。
- 饰品常规新增、复制、添加同款和实际 BOM 编辑不属于旧模板淘汰范围，继续可用。
- 不自动给旧模板去重、迁移或推断联动关系；新结构由用户按实际需要建立。
- 新流程最终调用现有饰品创建和 BOM 写入逻辑，避免建立另一套库存或生产身份。
- 新增入口的权限同时考虑饰品创建和配件选择能力，服务端必须校验，不能仅隐藏按钮。

清理在正式切换时执行，不因设计确认就立即操作正式库。先检查外键和所有引用、备份并列明清理记录数；只清理上述模板数据，禁止用宽泛级联清空波及实际 BOM 或其他业务表。迁移测试须验证旧模板已清空、新结构为空起步、已有业务记录及用量保持不变。

### 4.2 新数据的职责边界

建议实体：

| 实体 | 职责 |
| --- | --- |
| 结构 | 名称、说明、销售用量基准、修订号 |
| 结构位置 | 稳定标识、名称、顺序、默认配件和数量、是否逐件选配 |
| 搭配方案 | 所属结构、名称、修订号 |
| 方案差异 | 按位置引用的配件 / 数量覆盖 |
| 创建来源 | 可选的饰品创建来源与已解析配置记录，不参与生产时动态继承 |
| 批次请求 | 防重复确认的请求标识及创建结果 |

具体表设计在开发时结合 ORM、事务与迁移测试确定，不直接照搬 Demo 的浏览器内存对象，也不受旧模板数据格式和接口兼容限制。旧表若被移除或重建，必须通过显式迁移完成，不能依赖应用启动时自动清空数据。

### 4.3 后端解析与安全校验

- 使用同一解析服务为预览和创建提供结果，避免前后端各算一份后产生差异。
- 解析优先级：结构默认 → 所选方案 → 逐件选配 → 单件覆盖 / 删除 / 新增 → 最终按配件合并。
- 接口校验位置归属、方案归属、配件存在性与可用性、数量精度及允许范围。
- 用量采用 Decimal，与现有 BOM 的数量精度匹配，不使用二进制浮点进行累加和持久化。
- 采用乐观修订校验或等价机制，防止预览后配置变化以及多人覆盖编辑。
- 创建整批在同一个数据库事务内完成；任意行失败不得留下部分饰品或半套 BOM。
- 重复点击确认、请求重试和网络超时后的重试不得重复创建，需有服务端幂等保障。
- 未确认前不写入饰品、BOM、库存、订单或生产记录。
- 不接受客户端传任意目标饰品编号来覆盖旧 BOM；第一版批量接口只创建新饰品。

## 5. 用量与单位

Demo 的“链长 5cm”等均为示意，不是实际业务参数，也不能作为正式种子数据。

- BOM 用量采用配件真实库存单位，页面同时显示单位和销售基准。
- 若链条库存单位是克，不能把厘米数直接写进数量字段用于扣库存。
- 第一版没有经确认的换算规则时，只录入库存单位下的实际用量；工艺长度可独立备注，不混入库存数量。
- 若未来需要厘米与克换算，必须明确对应配件、换算依据和精度，再设计显式换算功能。
- 不按珠子尺寸、饰品名称或类目自动猜数量、链长或销售单位。

## 6. 已生成饰品与在制批次的区别

第一版保证：结构和方案修改不会自动修改已经生成的饰品 BOM，也不会通过新工作台批量覆盖旧饰品。

**这不等于已经实现投产批次的用料版本锁定。**

- `services/handcraft.py` 与 `services/handcraft_receipt.py` 的部分逻辑仍读取当前实际 BOM。
- `services/order_cost_snapshot.py` 的完成时成本快照不是投产用料快照。
- 不在本功能中顺手改写已投产批次或推断历史 BOM。
- 生产版本锁定要另行核对投产、领料、收回、损耗和撤销路径，并独立设计迁移与回归验证后再实施。
- 在该改造完成前，不对外承诺“任意修改饰品实际 BOM 都不会影响在制计算”。

## 7. 本轮范围与非目标

正式版第一阶段：

- 结构、组成位置与搭配方案的保存和复用。
- 批量表格、逐件选配、单件调整及明确 BOM 预览。
- 替换旧模板模块并清理全部旧模板数据，不做兼容或迁移旧模板。
- 仅创建新饰品及其确定 BOM，保留已有饰品、实际 BOM 和与模板无关的业务功能。
- 服务端权限、数据校验、事务、并发修订与重复提交保护。
- 本地测试与独立预览，用户确认后再另行授权提交、推送和部署。

不包括：

- 款式 / SKU 全面重构、重新编号、合并库存。
- 自动给旧模板去重或自动推断搭配方案。
- 自动批量更新已有饰品或已投产单据。
- 配件长度与重量换算公式。
- 生产 BOM 版本锁定或历史生产数据回填。

## 8. 验收标准

1. 两种组成不同的结构都可保存、编辑、另存，位置可自由命名。
2. 一个结构的两种搭配可同时改变配件与多个用量，不需复制整个结构。
3. 同批四行选择四种吊坠，只生成四件饰品，不生成全部组合。
4. 本批默认、单独指定方案和单件覆盖的优先关系清晰且可验证。
5. 单件新增 / 删除 / 替换不影响其他行或公共结构。
6. 删除位置后不兼容方案会阻止创建，不会加回已删除位置。
7. 最终 BOM 没有待选择配件、非法数量或含糊的库存单位；重复配件用量正确合计。
8. 修改结构与方案不修改已生成的实际 BOM；旧模板模块已替换、旧模板数据已清理，常规新增、复制、添加同款及实际 BOM 编辑回归通过。
9. 一行失败整批无写入；重复确认和请求重试不重复生成；预览陈旧会被拒绝。
10. 权限不足、跨结构方案 / 位置和篡改请求不能绕过服务端校验。
11. 桌面与手机均可完成流程；批量表窄屏可横向滚动，弹窗及关键按钮可用。
12. 使用隔离测试库验证，不重置现有预览库，也不在正式库运行测试。
13. 模板清理前后，已有饰品、实际 BOM、库存及历史单据的内容和记录数保持不变；清理不能由每次应用启动自动触发。
