- 本地正式入口：`http://localhost:5173/handcraft-output`，需要登录具备手工权限的账号。
- 商家管理的手工商家“查看产出”，以及饰品／配件详情的“查看手工产出”带入对应筛选；快捷入口包含归档，也受手工权限限制。

- 四个查询接口均只读；不改库存、耗料、付款、成本、损耗确认及结清规则，也不改变原“手工汇总”的日期口径。

## 统计口径

1. 只纳入 `processing`／`completed` 手工单的产出来源，不纳入 `pending` 草稿。无实收、部分实收和已结清来源均保留。
2. “已发出制作”取产出来源预期数量，不取材料发出数量。
3. “累计实收”聚合真实产出回收明细：产出来源关联非空、材料来源关联为空、数量大于零。材料退回、自动耗料、旧 `received_qty` 计数不当作实收。
4. 损耗按手工单、产出来源和类型核对。先独立聚合回收、损耗，再关联来源，防止多批回收与损耗连接时重复计数。
5. 尚未收回逐来源计算 `max(预期产出 − 累计实收 − 已确认损耗, 0)`，再汇总；一条来源的超收不会抵掉另一条来源的欠收。
6. 按商家、商品类型／编号、来源单位汇总；底层来源保持独立。饰品与配件同编号用 `jewelry:编号`／`part:编号` 区分。
7. 各单位分开显示，不跨单位相加，不推测换算。批次保留原单位，若与来源不同明确提示核对。实收百分比与“已结清”分开理解：实收加损耗覆盖预期即可结清。

## 筛选与时间

- 商家、产出均可多选；不选代表全部。同类取并集，商家与产出取交集，最多各 100 个。
- 默认全部时间，提供本周／本月／上月／自定义。周一为一周起点，使用北京时间自然日。
- **日期只筛制作任务的发出日期**。所选任务的累计实收包含截至当前的所有回收，包括其他月份的回收。
- 回收进度在来源层筛选后再汇总：尚未收回为实收 0 且有余量；部分收回为实收大于 0 且有余量；已结清为余量 0。
- 单据范围：正常、历史归档、全部。按商家／按产出切换保留条件。
- 自定义日期缺失、无效或起止颠倒时不发查询；接口同样校验参数。

## 发出时间兼容

- 在 `handcraft_jewelry_item` 新增 nullable `dispatched_at TIMESTAMP`，没有新增业务表。
- `database.ensure_schema_compat` 启动时幂等增加缺失列，**不回填历史**。
- 发出校验通过后，给本次产出来源统一记录北京时间；制作中追加产出记录追加时间，待发出追加不提前记录。失败发出不记时间，事务回滚规则不变。
- 历史 `NULL` 使用手工单 `created_at` 的日期，并在总览、来源、口径中标注“单据日期参考（非准确发出日）”。日期筛选也按此参考值选取，不能据此声称已还原实际发出日期。
- 如果历史发出时间与单据日期都缺失，仅在全部时间可见，来源显示日期缺失。

## API 与分页

均位于已有手工汇总 router 下，继承 `handcraft` 权限：

| GET 路径（`/api/handcraft-summary` 下） | 用途 |
| --- | --- |
| `/output-overview` | 全局单位指标、分组数量及完整分组页 |
| `/output-options` | 商家及类型化产出选项；产出搜索 `q`，保留 `selected_keys` |
| `/output-sources` | 指定商家、产出、单位的独立来源页，沿用当前筛选 |
| `/output-sources/{source_id}/receipts` | 指定已发出来源的真实回收批次页 |

- 主筛选重复参数：`supplier_names`／`output_keys`，另有 `date_from`、`date_to`、`progress`、`archive`。
- 总览 `view=merchant|product`，主页面每页 10 个完整商家／产出分组，接口单页上限 50 组。顶部指标覆盖**全部筛选结果**，不是本页小计。
- 来源与批次懒加载，每页 20 条，接口单页上限 100 条；无 N+1 查询。仅本页不超过 20 个汇总行时允许批量展开来源。
- 产出选项默认返回前 50 款，超出时提示搜索；已选项始终保留，选项故障不清空已选条件。
- 来源、批次及总览都保护旧响应，切换条件／销毁页面后旧请求不会覆盖新结果。查询失败隐藏旧指标，提供重试；分页越界会回到有效页。
- 路由安全记忆仅保存白名单条件、视角、页码，不存任意返回 URL。详情通过显式 `from=handcraft-output` 返回，直接打开详情不继承旧上下文。
