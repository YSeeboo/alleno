## 统计口径

### 已发出

列顺序：商家、发出天数、ID、配件、发出数量、单位、重量、产出、发出日期、备注、手工单号、回收单号、关联订单号。

- 每条 `HandcraftPartItem` 为一行，保留原明细身份，不按商品跨单合并，也不因多产出／多回收批次重复数量。只纳入已发出的 processing／completed 手工单，不包含 pending 草稿。
- 发出数量调用现有有效实配 SQL：原子配件仅在有对应勾选记录且实际数量非空时覆盖计划数量；组合配件仍按原明细数量。
- 重量沿用详情的配货记录口径：原子配件取对应记录及单位；组合配件将原子重量折算 kg 合计。没有重量不虚构零值。
- 日期取手工单 `created_at` 的北京时间日期；未结清且未归档的来源显示 `max(0, 今天－单据日期－1)` 天，保持电镀计天习惯。可按发出天数排序，已结清／归档行不显示运行天数。
- 保留已发出的结清来源并使用浅灰样式；不将“结清”误解为没有发生过发出。

### 材料与产出关系

- 匹配同一手工单内正数的当前 BOM 用料关系：饰品的直接配件及组合配件下级、组合配件产出的下级用料。
- 递归 CTE 使用 `UNION` 去重，支持多层组合，也可终止旧数据中的循环。零／负数 BOM 不提供用料证据；组合产出自己不被当成自己的材料。
- 明确标注「同单当前 BOM 关系推导」，不是历史用料快照或精确分配。没有依据显示「未能匹配产出」，不通过“共享某个原子配件”猜测两个无关组合之间的关系。
- 多产出共用材料在同一材料来源行内列出，发出数量仍只计算一次。回收单链接只来自这些匹配产出，不混入同单其他产出的回收单。

### 已回收

列顺序：商家、ID、产出、预期回收数量、实际回收数量、单位、未回收数量、损耗、发出日期、回收日期、备注、手工单号、回收单号、关联订单号。

- 每条 `HandcraftJewelryItem` 为一行，包括饰品和组合配件产出；同商品在其他手工单或其他明细上仍保持独立。尚无真实回收批次的已发出产出也保留，以支持全损等情况。
- 预期数量来自原产出计划数量，单位来自原明细，不使用当前商品主数据覆盖。各回收批次另行展示其实际回收明细单位。
- 实收只累计有效的产出来源 `HandcraftReceiptItem`（产出外键非空、材料外键为空、数量大于零），不读取包含损耗的产出 `received_qty` 作为实收。
- 不计入材料剩余退回，不把自动 BOM 耗料或已确认损耗当作真实回收。
- 未回收＝`max(0, 预期－累计真实回收－已确认损耗)`；未收差额不会自动转成损耗。
- 回收日期筛选只决定是否选择来源：命中任意一个回收批次即显示该来源，主行始终保留全部批次累计实收。展开逐批展示日期、数量、单位、回收单及对应备注，并标出范围内／范围外。
- 原来源备注、手工单备注、回收明细备注、回收单备注明确区分。批次不因属于同一回收单而被错误合并。
- 关联订单只通过当前明细的 `OrderItemLink` 及对应 `OrderTodoItem` 取出，不把同手工单其他来源的订单混进来。

## 筛选、分页与导航

- 保留单据范围（正常／归档／全部）、商家、日期、配件 ID、产出 ID、订单 ID；**没有泛关键词筛选**。配件／产出字段支持输入 ID 或名称，订单字段按关联订单 ID 查找；组合条件按 AND 应用。
- 后端在 SQL 中对原来源计数、筛选及分页（默认每页 30，最多 200），随后批量获取产出、批次、订单、重量、损耗。查询次数不随页内来源或批次数量线性增长，无逐行接口加载。
- `/api/handcraft-summary/dispatched` 和 `/api/handcraft-summary/received` 都是只读接口，复用模块级 `handcraft` 权限。
- 汇总两个方向在路由中分别保留条件和页码：已发出使用普通字段；已回收使用 `in_` 前缀。改筛选只重置当前方向页码，清空只影响当前方向。原两张列表的记忆仍使用原有字段和独立条目。
- ID／名称输入 300ms 防抖；切换方向、快捷新建或打开单据前刷新待提交输入。请求版本号及卸载保护防止旧响应覆盖新筛选。
- 单据／关联订单链接携带显式 `from=handcraft-summary`，返回目的地只能是正规化后的汇总地址，没有外部可注入的 return URL。手工来源详情和回收详情标出对应原明细；“返回汇总”恢复两个方向的条件和页码。
- 新建取消、新建成功后的详情、回收成功后成本变化的跳过／确认分支均保留显式汇总来源；直接进入原新建／详情页不继承旧的汇总返回状态。
- 单据／新建页仍独立展示，不套入 Tab 外壳；手机表格内部横向滚动，批次详情宽度跟随可视面板。

## 确认损耗

- 复用 `POST /api/handcraft/{order_id}/items/{item_id}/confirm-loss`，`item_id` 是原产出明细 ID；包括组合配件产出在内均按现有接口传 `item_type: "jewelry"`。
- 只允许差额内的正整数数量，可选扣款及原因，防重复提交；归档单据不提供确认入口，后端仍有原有归档保护。
- 已确认损耗独立显示，部分确认后可继续，结清后不再提供入口。确认失败不改变本地数量，保留弹窗；成功重新读取真实汇总。
- 旧数据若存在“来源回收计数”与真实批次／损耗不一致，不捏造批次。提供的可确认上限同时受现有来源计数约束；无法安全确认时提示核对来源明细，不通过汇总绕过旧接口规则。

## 后续修复：产出结清即可完成（2026-11-17）

### 完成规则

- 有产出的手工单，**每一条产出明细**结清即允许完成，包括饰品与组合配件产出。包装等材料的剩余余额不再阻止整单完成；不同产出明细的多收／少收不能互相抵消。
- 完成判断沿用产出 `received_qty` 结清计数，该计数已含真实回收及已确认损耗，不再次叠加损耗。汇总中的“实际回收数量”仍只计真实批次，不因完成而改变。
- 无产出的手工单沿用材料有效数量结清规则：原子配件仅在已勾选且实际数量非空时使用实配数量；组合配件仍使用原明细数量。空单不允许完成。
- 创建真实回收、确认损耗后重新判断并自动完成。删除或减少产出回收导致未结清时，自动退回“进行中”并清空完成时间；仅退回材料或撤销材料退回，不会使已结清产出的整单重新打开。
- 待发出单不可跳过发出直接完成；归档单保持只读。重复完成请求不重复变更完成时间。

### 之前卡在“进行中”的单据

1. 打开手工单详情，核对产出明细是否全部结清。
2. 点击底部“确认完成”并确认。产出未结清或产出明细加载失败时按钮不可用。
3. 后端重新校验结清条件，通过后**只更新整单状态和完成时间**，不补造回收单、不增加库存、不自动退回材料、不伪造材料结清计数。剩余材料仍按实际业务单独处理。

详情使用现有 `PATCH /api/handcraft/{order_id}/status`；旧看板的完成入口也改为复用同一安全校验，移除其自动补回收和入库的强制完成逻辑。未进行历史批量回写，也未修改生产单据。2026-11-18 用户另行授权本次修复随超量回收一并提交、推送及部署，实际结果见 [receipt-overage.md](receipt-overage.md) 所列服务器发布记录。
