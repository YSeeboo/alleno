# 电镀汇总新建快捷入口

## 布局与行为

- 采用局部 Demo 的方案 A：「电镀汇总」标题右侧固定显示「新建电镀单」「新建回收单」，不随已发出 / 已收回、归档筛选或空数据隐藏。
- 两个入口为平级操作，统一使用绿色实底按钮，加号图标、尺寸及交互状态一致，不区分主次；内容宽度不超过 620px 时，双按钮移到标题下方等宽并排。
- 直接打开既有 `/plating/create` 或 `/plating-receipts/create`，使用 `from=summary` 标记来源。仍受原有 `plating` 路由权限保护，不复制创建表单。
- 从快捷入口打开时，页头显示「返回汇总」；返回或取消均恢复汇总的方向、商家、日期、关键词、排序、归档筛选和分页。立即点击快捷入口前尚未完成防抖的搜索会先同步，按既有规则重置分页。
- 普通列表入口或直接打开新建页不受历史汇总记录影响，保留原返回行为。原列表新建按钮保留。
- 创建成功仍进入单据详情，并复用既有「返回汇总」。新建电镀单仍为待发出，不自动确认发出；回收入库、付款及成本差异确认流程不变。

## 本地验证（2026-11-17）

- 前端全部 75 项测试通过，包含新增 4 项导航回归测试；生产构建通过，仅有既有 auth store 导入提示。
- 桌面、手机各 31 项隔离交互检查通过：快捷入口、返回 / 取消保留状态、立即搜索、原入口兼容、成功跳转详情、详情返回汇总及不自动发出。
- 320、390、620、768、1024、1440px 六档宽度无页面横向溢出，双按钮可见且不越界；桌面及手机截图已检查。
- 浏览器接口全部由内存适配器模拟，未知请求拒绝。没有写入数据库、创建真实单据或上传 OSS。
- 上述为本地实现阶段的验证记录。2026-11-17 用户已授权与手工管理及手工汇总一起提交、推送并部署。`frontend/mockups/` 下的局部 Demo 仍为 Git 忽略的本地参考文件，不纳入发布；实际发布记录见服务器 `/var/backups/allen_shop/releases/`。
