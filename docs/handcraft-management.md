# 手工管理整合

> 本文记录先完成的两 Tab 整合阶段。之后经确认新增「手工汇总」，现为三个 Tab，首次默认汇总；已有最后 Tab 记忆不变。当前汇总的接口、统计口径及追加验证见 [handcraft-summary.md](handcraft-summary.md)。下列两 Tab 描述、当时未发布的状态和 86 项测试数字保留为该阶段的历史记录。2026-11-17 用户已授权将这些修改与手工汇总、电镀快捷入口一起发布。

## 本轮范围

- 侧边栏展开、收起和手机菜单统一为一个「手工管理」入口；列表、新建及详情页均保持该入口高亮。
- `/handcraft-management` 为统一入口，内部仅有「手工发出」「手工回收」两个 Tab。页头、绿色选中线、图标、间距和手机布局参考电镀管理，不新增汇总或商家对账页面。
- 保留 `/handcraft`、`/handcraft-receipts` 两个原列表地址，列表嵌入共享外壳，避免重复页头。原新建及详情地址仍独立展示，沿用原有返回行为和 `handcraft` 权限。
- 保留现有列表列、归档／状态／商家筛选、新建、详情、删除保护及五位回执编号跳转；窄屏表格在内部横向滚动，不撑宽页面。
- **不修改后端、数据库或业务规则**：本轮不允许超量回收，不改变库存、BOM 材料耗用、付款、成本更新及历史单据。
- 保留此前尚未提交的电镀汇总双绿色快捷按钮改动，不提交、推送或部署。

## 导航与筛选记忆

- 首次进入默认「手工发出」；`localStorage` 的 `handcraft-management:last-tab` 记住最后打开的列表 Tab，不记录新建或详情地址。
- `sessionStorage` 的 `handcraft-management:queries` 分别保存两个列表的筛选条件，与电镀管理使用独立的键。
- 发出列表记住 `archive`、`status`、`supplier_name`；回收列表只记住 `supplier_name`。默认正常单据、清空筛选以及不合法的参数不写入记忆。
- 继续使用原有 `supplier_name` 查询参数，详情中的「查看回收单」显式商家链接优先于历史记忆；当前列表清空条件不会被旧条件覆盖。
- 不保存扫码输入、回执码、预填载荷或详情 ID；存储损坏、不可用或被禁用时仍可正常导航。
- 筛选由路由驱动，避免同一次选择触发重复加载。请求版本和卸载保护阻止旧列表响应覆盖新筛选；离开列表后的扫码响应不再自动跳转。
- Tab 支持左右方向键循环切换，以及 Home / End，切换后同步焦点和 `aria-selected`、面板标签。
